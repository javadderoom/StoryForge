# StoryForge (AfsanehSaz) — World Cartographer Truth Audit

> **Audit Date:** October 2026
> **Auditor Perspective:** Brutal Critic & Systems Architect
> **Scope:** The Studio World Cartographer (`/cartographer`) — the PixiJS canvas, the land-sculpt brush, the terrain drafting tools, the layer panel, the entity palette, the inspector, the "AI Cartographer Oracle", and the Plan 19 coordinate refit — measured against the live production story (`story_mt4ofllt` / Faravand).
> **Method:** Every capability was traced from the UI control to the code that backs it, then checked against production data read through the Studio API. No capability is credited as "working" on the strength of its UI.

---

## 1. Executive Summary

The World Cartographer is **the most visually polished surface in the Studio** — a hardware-accelerated PixiJS canvas with a real boolean land-sculpting engine, hand-inked parchment coastlines, draggable pins and a deterministic coordinate refit. Underneath, roughly **80% of it is real** and a specific, identifiable **20% is theatre**: controls that persist data, appear in panels, report success in toasts — and change nothing.

The three findings that matter:

1. **The "AI Cartographer Oracle" is not AI.** It performs no model call of any kind. It joins consecutive locations with `Math.random()` midpoints and drops two hardcoded terrain features at fixed coordinates — then tells the author *"trade routes successfully generated by AI"*. Its own source comment reads `// Simulate intelligent generation connecting settlement pairs`. This is the single most misleading surface in the Studio, because a spinner and a success toast are exactly what a working AI feature looks like.

2. **The map stores more than it draws.** In production, **4 of 13 terrain features (2 peaks, 1 canyon, 1 oasis) are persisted, listed in the inspector and the layer panel, and render as nothing** — the renderer has no branch for those types. The same is true of three layer toggles (`valleys`, `timeline`, `factionBorders`) and one setting (`showGridCoordinates`) that gate nothing at all.

3. **Nothing about the map reaches the player.** No player-facing surface — web reader or Flutter — renders the map. Its only gameplay consequence is indirect: `location.coordinates` → `calculateMapDistance` → `calculateCaravanTravelDays` → travel ETA. The Cartographer is an authoring instrument whose output is a set of numbers, not a picture.

> **The pattern:** the Cartographer fails the way a well-designed mock-up fails — every affordance is present, every affordance persists, and only the final link to reality is missing. That is why the gap survived so long: each individual control looks alive.

### 2.2 The Land-Sculpt Brush — the deepest part of the system

Continuous stroke → organic stamp accumulation → boolean union/carve:

- `landSculptEngine.ts` `applySculptOperation` (L748) performs real polygon boolean operations with simplification, minimum-area and sliver rejection.
- The canvas accumulates interpolated stamps along the drag (`PixiCartographerCanvas.tsx:418–445`), renders a live stroke preview (`PixiCartographerEngine.renderBrushPreview`, L828), shows a brush cursor (L416), and commits the stroke on mouse-up (`PixiCartographerCanvas.tsx:466–490`) through paint/carve modes, brush size and roughness.
- Backed by **~1,900 lines of tests** across three suites (`landSculptEngine.test.ts`, `.invariants.test.ts`, `.adversarial.test.ts`) — union, carve, inland-lake holes, river splitting, sliver rejection, sub-100 ms union of 15 stamps.

This is production-grade work.

### 2.4 Persistence & Gameplay Linkage

- Terrain, pins and settings persist through `StudioStoryContext.updateMapData` (`L2524–2540`), which writes **both** `worldBible.mapData` and `worldBible.ontology.mapData` so the data survives the world-bible/manifest merge in `storyRepository.getStory`.

After Plan 19 those numbers are derived from lore and topology instead of auto-allocated anchors — the map is now an *input* to gameplay, not decoration.

## 3. What Is Just For Show

### 3.1 🔴 The "AI Cartographer Oracle" performs no AI at all

`web/src/components/cartographer/CartographerAiOracleModal.tsx`

- **No network call exists in the file.** Not a hidden fetch, not a route — nothing.
- The generator's own comment says so: `// Simulate intelligent generation connecting settlement pairs` (L58).
- *Caravan Network* mode (L60–90): walks `locations` in array order and joins each consecutive pair with a `Math.random()`-jittered midpoint (L67–68). It ignores geography, distance, faction, danger and the world's own lore.
- *Natural Terrain* mode (L99–129): adds **two hardcoded features at absolute coordinates** — `Thunder Ridge Crest` at (400,800)→(1100,920) and `Black Pearl Torrent` at (1100,930)→(1450,1350). Every world gets the same mountains in the same place.
- The **"Custom Guidance" input** (L38, rendered L224) is captured and **never read** — typing "hazardous mountain passes plagued by raiders" changes nothing.
- `isGenerating` (L244) shows a spinner, but `handleGenerate` has no `await` — the spinner can never paint before the work is already done.
- The toast reports *"trade routes successfully generated by AI"* (L93–97).
- A third mode, `'wilderness_hazards'` (L36), is declared in the state type with **no button and no branch** — dead code.

**Fix direction:** either make it real — a `/api/studio/cartographer/generate` route that reads the world bible and returns schema-valid routes and terrain the renderer actually draws — or relabel it as what it is ("procedural scaffolding") and stop claiming AI. The renderer already understands the schema a real generator would return.

### 3.2 🟠 The theme picker changes nothing on screen

The header offers five map styles (`CartographerHeader.tsx:176–186`) and persists `settings.theme`. The renderer never reads it: `PixiCartographerEngine.ts` imports a single fixed palette (`VINTAGE_PARCHMENT`, L20) and colours everything from it. `THEME_PALETTES` in `cartographerEngine.ts` (five palettes) is referenced only by the test suite.

### 3.3 🟠 The ruler measures nothing

The toolbar tooltip promises *"Measure leagues & caravan travel days"*. The tool draws a line and two dots (`PixiCartographerEngine.ts:811–822`) — **no number, no distance, no travel time**. The underlying math exists and is battle-tested in the travel engine; it was simply never wired to the ruler.

### 3.4 🟠 Terrain types that render as nothing

The renderer branches on `continent`, `island`, `forest`/`desert`/`swamp`/`tundra`, `lake`, `river`, `mountain_range`. It has **no branch for `valley`, `peak`, `canyon`, `oasis`, `chasm`, `volcano`, `plains`, `wasteland`, or `arcane_anomaly`** — yet all of them are valid `MapTerrainType` values (`types/world.ts:675–695`) and the **Valley & Chasm tool creates `valley` features on purpose** (`PixiCartographerCanvas.tsx:564–597`).

**Production impact** — the 13 persisted terrain features of `story_mt4ofllt`:

```
continent(polygon) = 1   island(polygon) = 2   lake(polygon) = 1
mountain_range(points) = 1   river(points) = 2   forest(polygon) = 1   desert(polygon) = 1
peak(no geometry) = 2   canyon(points) = 1   oasis(no geometry) = 1
```

Four of thirteen — **two peaks, one canyon, one oasis** — are stored, listed in the inspector, and invisible. Two of them have no geometry at all (`peak`, `oasis` have neither `polygon` nor `points`).

### 3.5 🟡 Dead layer toggles and settings

The renderer consults: `grid`, `terrain`, `biomes`, `water`, `mountains`, `caravanRoutes`, `settlements`, `labels`, `npcs`, `bestiary`, `relics`, `deities`.

Never consulted: **`valleys`** and **`timeline`** ("Historic Battlefields" — both offered as toggles in `CartographerLayerPanel.tsx:62–67`, `106–111`), **`factionBorders`** (present in the settings type, in the defaults and in production data, but with no toggle and no branch), and **`showGridCoordinates`** (`types/world.ts:752`).

### 3.6 🟡 Lore pins are author-only decoration

`mapData.placements` renders as coloured dots, but **nothing outside the Cartographer reads it** (`page.tsx:323–345` and `PixiCartographerEngine.ts:167` are the only consumers). Pinning an NPC on the map does not move that NPC in the world; the NPC's actual position is `npc.currentLocationId`, which the map can edit but the pin does not.

### 3.7 🟡 Seed terrain never appears on its own

`createSeedTerrainFeatures` (`cartographerEngine.ts:155`) generates a plausible world, and `getOrInitializeWorldMapData` (L435) falls back to it when a world has no map. But the page uses that memo **only for settings** (`page.tsx:69–73`), while the canvas renders `worldBible.mapData?.terrainFeatures` (`PixiCartographerEngine.ts:166`). A fresh world therefore opens on an **empty parchment**; the seed terrain only materialises when the author changes a layer toggle, which persists the memo's map data as a side effect (`page.tsx:121–129`).

### 3.8 🟡 Leftovers from the pre-Pixi SVG renderer

`pointsToSmoothSvgPath` (L489), `polygonToSvgPath` (L519) and `generateDefaultCaravanWaypoints` (L528) belong to the old SVG pipeline. Only the test suite calls them.

### 3.9 🟡 The "e2e" suite is a specification oracle, not an end-to-end test

`web/src/lib/engines/world/e2eMapCanvas.test.ts` (1,533 lines, four systematic tiers) never imports `PixiCartographerEngine` — it re-implements a reference brush/contour model and asserts against that. The **actual renderer and the React canvas layer have no browser-level coverage at all.**

### 3.10 🔵 Players never see the map

The only page that imports the Cartographer is `/cartographer` itself. The web reader does not render it, and the Flutter app contains **zero** references to `mapData`, `coordinates` or any map view. Its sole gameplay output is the travel-ETA derivation in §2.4.

## 4. What This Means

1. **A missing map is not a missing feature.** An author who believes the map is the reader's window into the world is wrong; what the map really does is *compute the numbers the travel engine uses*. The Studio copy should say so.
2. **The Oracle is a trust problem, not a features problem.** A tool that fakes competence while claiming to be AI will, eventually, generate a map an author trusts. It is the highest-priority item in this audit despite being the smallest.
3. **Silent persistence is worse than no feature.** Dead toggles and invisible terrain teach the author that the map understands more than it does — the data is there, the panel says so, the picture disagrees.
4. **The sculpt brush proves the team can build this properly.** The 20% that is fake is not a capability gap; it is a set of unbuilt links in an otherwise serious tool.

## 6. Delivered Alongside This Audit

### 6.1 Undo / redo for every Cartographer action

The Cartographer had **no undo at all** before this change — one mis-click on the land brush or a dragged pin could only be repaired by re-editing by hand.

- **Engine:** `web/src/lib/engines/world/cartographerHistory.ts` — a pure, unit-tested history model (14 tests). `past` holds the pre-state of each action, `future` holds undone actions, the stack is bounded at 50 entries.
- **Restore semantics:** undo/redo **merges** the fields the Cartographer owns (`CARTOGRAPHER_LOCATION_FIELDS`, `CARTOGRAPHER_ROUTE_FIELDS`) instead of replacing whole objects, so a lore field edited elsewhere — a threat clock, a parent link, special rules — survives an undo of a pin move. Entities the Cartographer added disappear again; entities it deleted come back; NPC records are never replaced, only their stationing is restored.
- **Typing coalesces:** the inspector writes on every keystroke, so a burst of the same action inside an 800 ms window is folded into **one** undo entry (keeping the earliest pre-state) — one Ctrl+Z reverts the whole edit instead of one character.
- **Page wiring** (`web/src/app/cartographer/page.tsx`): every authoring action is wrapped in `commit(label, fn)` — add/edit/delete terrain, the sculpt stroke, add/move/delete pins, add/edit/delete routes, NPC stationing, and the Plan 19 auto-fit.
- **Shortcuts:** `Ctrl+Z` / `Cmd+Z` undo, `Ctrl+Shift+Z` / `Ctrl+Y` redo. Both are ignored while the caret is in a text field, so the browser's native text undo still works in the inspector.
- **UI:** undo/redo buttons in the header with the next action's name in the tooltip ("Undo: Sculpt terrain"), plus the existing Plan 19 auto-fit undo pill.

**Known limits:** the history lives in page state and is not persisted across a reload; it covers Cartographer actions only (an edit made in the Locations tab while the Cartographer is open is *not* on the stack, though the merge keeps such fields from being clobbered by an undo).
